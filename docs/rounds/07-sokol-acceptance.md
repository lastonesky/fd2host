## 36. 第 36 轮：sokol 与 GDI 同 tick 逐像素验收（2026-10-06）

### 36.1 背景

§34 已经把验收标准从"同帧"改判为"同一 guest tick"（`--shot-tick`），但当时按用户指示
**停止了逐像素对拍**，两张对照 BMP 也没留下 —— 这是 `PROGRESS.md` 下一步第 3 条唯一没做的部分。
本轮补上：先验基线，再做跨后端比较。

### 36.2 第一次尝试（反面教材）：取样点选在片头转场

按老经验取 `--shot-tick=290`，先做同后端基线：

```
GDI run1 vs GDI run2（同 tick 290，每次先删 FD2.TMP）：36949/64000 px（57.73%）
之前那组（条件没控住）：                                  38613/64000 px（60.33%）
```

看图才明白：**一张是黑场转场帧，一张是已经入戏的场景帧** —— 同一个 tick 落在了不同的
动画阶段。tick 只钉住宿主的 18.2 Hz 时钟；片头那一段的状态还取决于"启动到进该场景花了多久"。
**基线 60% 意味着这次跨后端比较根本没有判据**（已记 `PITFALLS.md` §8-53）。

顺带澄清一个概念问题（用户当场质疑）：**BIOS tick 规则与后端选择是两件事** ——
tick 是"什么时候抓"，GDI/sokol 是"图从哪来"；跨后端对拍必然要两个后端各出一张图，
GDI 只是**临时**出对照图的那一侧，不是回到 GDI 流程。

### 36.3 正确取样点：静止画面

取样点改到 **`--shot-tick=600`**（标准 autokey 配方 `5000:SPACE;2500:RETURN;2500:RETURN;
2500:DOWN,RETURN` 走完、停在静态等键画面），每次跑之前删 `FD2.TMP`，连跑两次做基线：

| 项 | 结果 |
|---|---|
| **基线**（sokol vs sokol，同 tick 600） | **0 / 64000 px（0.0000%），max delta 0** |
| **跨后端**（`-Render gdi` 的图 vs sokol 的图，同 tick 600） | **31 / 64000 px（0.0484%）**，容差 0.5% 内 |
| 差异位置（逐像素 bbox） | 全部在 **x[40..53] y[141..144]** 一块 14×4 小区；ASCII 局部放大确认是**同一个动画元素的相位差**（sokol 侧多一小块亮斑），不是调色板/通道序/缩放的系统性差异 |
| 状态一致性 | 同 tick 下 `age 37235 ms`（sokol）vs `37282 ms`（GDI）、帧数 **5937 vs 1185** ⇒ 状态由 tick 钉住，与后端帧率无关（§13.8 的论断得到像素级证实） |
| 回归 | 切回默认 sokol 构建后 `regress.ps1` **8/8 PASS**、`FD2.TMP = 207360` |

差异为什么是"相位差"而不是 bug：同一个 BIOS tick 内 guest 还会多跑几个循环，
那个 14×4 的元素按循环推进（约 159 fps 与 32 fps 的后端在同一 tick 上落点略有不同）。
它被 0.5% 容差覆盖，且**位置可定位、性质可解释**，符合"差异必须能说明白"的判据要求。

### 36.4 结论

- **第 2 步（显示层换 sokol）验收通过**：`PROGRESS.md` 下一步第 3 条收口。
- 验收标准再补一条前置条件：**先做同后端基线自比，基线必须 0 px，再比跨后端**
  （`BACKEND.md` §13.10、`PITFALLS.md` §8-53）。
- **GDI 不进日常循环**：本轮只临时 `-Render gdi` 编了一次出对照图，之后立即切回默认 sokol；
  以后只有需要"参考实现"时才重建。

### 36.5 判据

`framediff.ps1` 三组数字（0 px 基线 / 31 px 跨后端 / bbox 定位）、
日志 `guest tick 600`（两后端同 tick、帧数 5937 vs 1185）、
`regress.ps1` **8/8 PASS** + `FD2.TMP = 207360`。
