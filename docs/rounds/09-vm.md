## 39. 第 39 轮：`0x15F84` 脚本 VM 转译 + 对拍 + 接入（2026-10-06）

### 39.1 目标与起点

`sub_15F84`（1380 B，126 个直接调用点）是每一句台词、每一次肖像切换、每一个打印数字
必经的解释器。**起点状态：原版机器码**——`src/le.c` 把 `FD2.EXE` 原样映射进游戏地址空间，
`repl.c` 只给已对拍的函数写 5 字节 `jmp`，它不在表里，所以 `--replace=none` 与 `all`
下跑的是同一段机器码。周边（`dlg`/`rec`/`rle2`/`gfx`/`res`）早已转译，**中间这块还是汇编**。

本轮把它变成 `src/game/vm.c`，走完七步流程。

### 39.2 测绘（这一步纠正了两个"看起来不可能"的点）

**① ABI：9 个 cdecl 栈参数，不是 14 个寄存器参数**（§37 已先纠正，本轮落地验证）：
调用点九个 `push` + `add esp,24h`；入口 `push 5Ch; call 0x3702F` 是 Watcom 栈探针
（`0x37042` = `_chkstk`）。参数语义靠调用点常量反推钉死：

| 参数 | 实测值 | 含义 |
|---|---|---|
| 1 `stream` | `dword_53A7D` 等 | 词流容器：`stream + (int16)stream[2*sub]` 是子流起点 |
| 2 `sub` | 0xA / 0x1A1 / 0x1B4 … | 选哪条子流 |
| 3 `addr` | `0xA0000` `0xA9F23` `0xAB6E3` | **VGA 写地址**（mode 13h 线性地址，不是坐标） |
| 4 `pitch` | 320 | 每扫描线字节 |
| 5/6/7 | 205 / 76 / 74 | 前景色 / 阴影像素色 / 16×16 格填充字节（`0x4ED7A` 的 a5/a6/a7） |
| 8 `line_step` | 19 | `-2/-3` 换段落时 `cur = start + pitch*19*行号` |
| 9 `wait` | 1 | 非 0 = 打字机模式（每字 `dlg_type_step`） |

**② `case -1` 的 `JUMPOUT(0x15309)` 不是跳飞，是共享尾声**：`0x15309` 落在
`sub_15055` 的尾巴上（`add esp,24h; pop ebp/edi/esi/ebx; retn`），两个函数帧完全相同，
编译器把 epilogue 合并了 ⇒ `-1` 的语义是 **`return cur`**（把当前写地址交回去，
`-4/-5` 的递归正是靠它串起来）。

**③ EDI 是跨 opcode 持久的局部变量**，不是参数：
- 肖像 op 结束时 `EDI = DATO缓冲 + 缓冲首字节`（RLE 块起点），下次 op 继续用它；
- 只有 `-17` 且操作数 `== 39` 时**先用后赋**——此时读的是**函数入口的 EDI**，
  而调用方根本不设置 EDI（40 个调用点回查：`mov edi,…` 都是各自的局部量）。
  即"操作数 39 = 复用当前记录"，但**首次肖像操作就是 -17/39 属于未定义行为，无法复现**。
  处理见 §39.4。

### 39.3 opcode 语义（逐条对着反汇编钉死，`re/vm_15F84_*.txt` 留档）

| opcode | 行为 | 关键细节 |
|---|---|---|
| `-1` | 关框并 `return cur` | **只有 `box != 0` 才 `dword_53C67 = 0`**（`0x164B1 jz` 跳过清零）——见 §39.5 |
| `-2` | 换段落，不等键 | `line==3` 且在框内 → `sub_16E24` 滚动 + `line--` |
| `-3` | 换段落 + 等键 | 先滚，再 `if(框) sub_16559(0)`、`sub_16C57(1)`、`wait=1` |
| `-4/-5` | 递归子流 `dword_53AD9`/`53ADD` | 只透传 `pitch`，其余参数硬编码 `205,76,74,19,1`；`cur` 取返回值 |
| `-6` | 打印 `dword_53AE1` 的十进制 | `sprintf("%d")` 逐位当字形画，缓冲 `char[12]`（INT_MIN 正好 12 字节） |
| `-17/-18` | 按记录 id 开上/下框 | `rec_find(id)` 决定行数（2 或 0 / 0x70 或 0）；`id != 39` 才改用 `dword_53C1B` 并取其 `[7]` 当资源号 |
| `-19/-20` | 按表下标开上/下框 | `rec = dword_53A45 + 80*idx`，行数硬编码 2 / 0x70，**不调 `rec_find`** |
| 其它 | 画一个字形 | `cur += 16`；有键 → `wait=0`；`wait` → `dlg_type_step` |

`dword_53C67` 取值：`0` 关 / `0x728` 上框 / `0x9017` 下框；开框同时把文字原点改成
`0xA0B4F` / `0xA951F` 并清零段落计数。

### 39.4 写法（`src/game/vm.c`）

- **app-level**：全局按原地址读写（`dword_53C67`/`53A85`/`53C1B`…），`repl.c` 零包装接入。
- **服务走原地址**（`ORIG_DRAW/OPEN/RES/…`）：游戏里那些地址就是已接入的 C，
  对拍里则是被 hook 成记录桩——两侧同一世界（`typecheck` 的同款做法）。
- **递归直接自调用 `vm_run`**，不经过 `0x15F84`：这样对拍时"原版递归进原版、C 递归进 C"
  （若走地址，C 侧会掉进机器码，递归分支就测不到了）；游戏里则由 `repl` 的 `jmp` 汇到同一处。
- `-17/39` 首次即触发时打印 `vm: -17/39 … using the last rec_find record` 并退到
  `dword_53C1B`——**这是唯一无法逐位复现的路径，留了运行期探针**（判据见 §39.7）。

### 39.5 对拍（`src/vmcheck.c`，`build.ps1 -Target vmcheck`）

12 个被调函数全部 hook 成记录桩，**两边跑同一批桩、同一套脚本化返回值**：
每例比 **完整事件序列（callee + 参数 + 顺序）**、**VM 自己写的全局**
（`dword_53C67`/`53A85`/`53C1B`）与 **返回值**（递归串起来的最终写地址）。
词流由合法生成器产生（字形 / `-2` `-3` `-6` / 四种肖像 op 带操作数 / `-4` `-5` 递归，
每条子流必以 `-1` 收尾 ⇒ `p` 单调前进，终止性有保证）。

**它当场抓到我两个真 bug**（这就是 harness 有牙齿的证据）：

| 症状 | 根因 |
|---|---|
| `close(16386,2)` vs `close(16386,0)` | `-19/-20` 的行数 2/0x70 只传给了开框，**没写回 `mode` 槽**，关框时用了 0 |
| `dato(0)` 少一条，事件数 251 vs 250 | `-1` 里 `dword_53C67 = 0` 写成了无条件执行；原版只在 `box != 0` 时清零（子流收尾不清外层的框状态） |

另外两个是**生成器/harness 自己的坑**（也一并记下）：
- `-17/39` 首个肖像操作数被 `rnd()%64` 自己撞出来 → 强制改成非 39（§39.2③）；
- 构造用例把三个子流都指向同一条 `-4/-5` 流 ⇒ **无限递归爆栈** → 子流偏移分开。

失败输出带 **"first diff at event N"** 与前后 4 条对照窗口，定位靠它一次到位。
