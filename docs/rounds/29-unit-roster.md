## 59.1 这一批

| addr | usage | 转译 | 语义 |
|---|---|---|---|
| `0x1145A` | 2 | `unit_recalc(index)` | 从记录 `+37/+39/+3E`（有符号 16 位）起，对 8 个物品格中 `state & 0x40` 的槽累加 `tbl_602AD(slot[1])` 的 `+1/+5/+3/+7`，写回 `+48/+4A/+4C/+4E`，返回 `+4E` 的**完整 32 位**累加值 |
| `0x11506` | 24 | `unit_refresh_all(void)` | 外层角色表 × 内层队伍表：`+8` 身份匹配且（身份非 0 或 `rec_flag(i)==0`）时把角色记录整笔 `memmove` 抄回，清 `+22..+27` 六个 transient，`+5 &= 1`，视 bit0 同步 `+40<-+42`、恒同步 `+44<-+46`，再 `unit_recalc(j)` |
| `0x112A5` | 28 | `unit_add(id)` | 按 `tbl_61DA1(id)`（24 字节默认）+ `tbl_620A1(id)`（11 字节成长）构造一条新记录 append 到 `dword_53BFB`，随后 `dword_53BFB++`，返回 `unit_recalc(旧索引)` |

记录基址一律 `dword_53BF7 + 80u*(uint32_t)index`（机器码 `(i*5)<<4`，按 32 位无符号算）。
被调全部落在三类：CRT（`0x3702F` 栈探针、`memmove`/`memset`，约定不转译）、已接入的表访问器
（`0x4E8BC`/`0x4E838`/`0x4E821`）、已接入的 `0x34894 rec_flag`，以及本簇内的 `0x1145A`。

IDA 逐条核对确认了四个易错点，全部按机器码原样实现（差分对拍钉住）：

- **累加器是 32 位、只在写回时截成 16 位**：`0x1145A` 的 `+48..+4E` 用 `add [var],edx` 累加，
  返回的 `+4E` 值是**未截断的 32 位**（`mov eax,[var_10]`）。C 用 `int32_t` 累加、`uint16_t` 写回、
  返回 `int32_t`。槽的初始值用 `movsx`（有符号 16 位）。
- **`0x112A5` 的 HP/MP 成长项是 `(L-1)` 的 32 位运算**（`dec edx; imul`）：`L==0` 时 `(L-1)=-1`
  ⇒ 成长项为负。C 用 `(int32_t)G[6] * (L - 1)` 再截断到 16 位。
- **`0x112A5` 的 `+37/+39/+3E` 用了 `movzx ax, byte[G]`**，高 16 位仍是 G 指针的高位（x86 半寄存器
  写不改高半）；但随后只 `mov [un+37h], dx` 存低 16 位，高位不进结果 ⇒ C 直接按
  `(uint16_t)(D_word + G[k]*L)` 的无符号 16 位截断复现。
- **`0x112A5` 只写列出的字段**：`+17/+19`（后两格物品 id）与所有未列出的字节**保留目标槽残值**
  —— 对拍缓冲因此必须预置随机内容、不能清零（`+0x17/+0x19` 正是残值保留的观测点）。

`0x11506` 的双重循环顺序（外角色 / 内队伍）决定多次命中时最终值，逐字照抄。

## 59.2 对拍（`reccheck` 扩展）

沿用既有骨架（`le_reserve_address_space` → `le_open` → `le_map_and_relocate`；真游戏全局）。
新增的三组用例都跑**两份逐字节相同的副本**（原机器码跑 `obuf`、C 跑 `cbuf`），
判据 = **返回值 + `dword_53BFB` + 整块 64 记录 × 80 字节缓冲区逐字节**；
`unit_refresh_all` 另外断言**角色表（`unit_ch`）一个字节都没被改**。

| 函数 | 用例 |
|---|---|
| `unit_recalc` | 随机 `index`、四种槽形态（全空 / 全活 / 混合 / 固定 id）（2000 例）+ 构造：四形态配 `+37/+39/+3E` 取 `0x8000/0x7FFF` 边界 + 8 槽全活配 4 个物品 id |
| `unit_refresh_all` | 随机 `n1/n2∈0..64`、身份匹配/不匹配、`+5` bit0 随机（1500 例）+ 构造：身份 0 时 `rec_flag` 两路、非 0 身份恒抄、`+5` bit0 两路、3 个角色抢 1 条队伍记录的**顺序**、部分匹配 + 未匹配记录保留 |
| `unit_add` | 随机 `id∈0..31`、append 索引随机、缓冲预置随机残值（800 例）+ 就地改 `tbl_61DA1(0)` 的等级 `L∈{0,1,255}` 与 `D[0x0E..0x11]==0xFF` 分支（用完还原） |

结果 **36327 cases, 0 failures**（32010 → +4317）。`mapcheck` **97000/0** 与 `utilcheck`
**2200/0** 仍过（未扰动旧符号）。
